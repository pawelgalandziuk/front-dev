Introduction

Welcome to the Frontend Developer Guide.

This guide will help you understand the basics of frontend development, including HTML, CSS, and JavaScript.

Week 1 - HTML Structure

1. First of all

Each .html file has to start with this structure:

<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Your Page Title</title>
</head>
<body>
    <!-- Your content goes here -->
</body>
</html>
  • <!DOCTYPE html> -- Says to the browser: Its HTML5.
  • <html lang="en"> -- The root element of the HTML document, with a language attribute set to English.
  • <head> -- Contains meta-information about the document, such as character encoding and viewport settings.
    It can also contain <link>, which is an element used to link external resources like CSS files.
  • <meta charset="UTF-8"> -- Specifies the character encoding for the document, ensuring that it can display a wide range of characters correctly.
  • <meta name="viewport" content="width=device-width, initial-scale=1.0"> -- Ensures that the webpage is responsive and scales correctly on different devices, particularly mobile devices.
  • <title>Your Page Title</title> -- Sets the title of the webpage, which appears in the browser tab and is important for SEO.
  • <body> -- Contains the content of the HTML document that is visible to users, such as text, images, and other elements.

2. HTML Elements

HTML elements are the building blocks of web pages. They are represented by tags, which define the structure and content of the page.

  • <h1> to <h6> -- Heading elements, with <h1> being the most important and <h6> the least.
  • <p> -- Paragraph element, used for blocks of text.
  • <a> -- Anchor element, used for creating hyperlinks to other pages or resources.
  • <img> -- Image element, used to embed images in the page.
  • <ul>, <ol>, and <li> -- List elements, used for unordered and ordered lists.
  • <div> -- Division element, used as a container for grouping other elements together.
  • <span> -- Inline container element, used for styling or grouping text within other elements.
  • <form> -- Form element, used for collecting user input through various form controls.
  • <input> -- Input element, used for various types of user input within a form.
  • <button> -- Button element, used to create clickable buttons for user interaction.
  • <table>, <tr>, <td> -- Table elements, used for displaying tabular data.
  • <iframe> -- Inline frame element, used to embed another HTML page within the current page.
  • <script> -- Script element, used to include JavaScript code in the page.
  • <a href="URL"> -- Anchor element with a hyperlink reference, used to link to other pages or resources.

3. Semantic HTML5

Semantic HTML5 elements provide meaning to the structure of a webpage, making it easier for browsers and assistive technologies to understand the content.

  • <header> -- Represents introductory content or a set of navigational links.
  • <nav> -- Represents a section of the page intended for navigation links.
  • <main> -- Represents the main content of the document, unique to the page.
  • <section> -- Represents a standalone section of content, typically with a heading.
  • <article> -- Represents a self-contained piece of content that could be distributed independently.
  • <aside> -- Represents content that is tangentially related to the main content, such as sidebars or callouts.
  • <footer> -- Represents footer content for its nearest sectioning element, often containing metadata or links.

5. Keys attributes

Some key attributes in HTML include:

  • id -- A unique identifier for an element, used for styling and scripting.
  • class -- A class name that can be shared by multiple elements, used for styling and scripting.
  • src -- Specifies the source URL for media elements like images and scripts.
  • href -- Specifies the URL for anchor elements, linking to other pages or resources.
  • alt -- Provides alternative text for images, improving accessibility.
  • title -- Provides additional information about an element, often displayed as a tooltip.

6. HTML Tables

HTML tables are used to display tabular data. They consist of rows and columns defined by various table elements.

  • <table> -- The container for table elements.
  • <tr> -- Defines a table row.
  • <th> -- Defines a table header cell.
  • <td> -- Defines a table data cell.

7. HTML Media

HTML media elements allow you to embed audio and video content into your web pages.

  • <audio> -- Embeds audio content, with controls for playback.
  • <video> -- Embeds video content, with controls for playback.
  • <source> -- Specifies multiple media sources for audio and video elements.

8. HTML Iframes

HTML iframes allow you to embed another HTML document within the current page.

  • <iframe> -- Embeds an external HTML document within the current page.
  • src -- Specifies the URL of the document to be embedded.
  • width and height -- Define the dimensions of the iframe.

9. More useful elements

A few extra elements that come up often and are good to know:

  • <figure> and <figcaption> -- Groups media (like an image) together with a caption describing it.
  • <blockquote> -- Marks a section as a quotation from another source.
  • <details> and <summary> -- Creates a native expandable/collapsible section, no JavaScript needed.

Summary

In summary, HTML is the foundation of web development, providing the structure and content of web pages. Understanding HTML elements, attributes, and semantic structure is essential for creating accessible and well-structured websites.

Week 2 - CSS Styling

CSS (Cascading Style Sheets) controls how HTML elements look and how they are arranged on a page. It is used for colors, fonts, spacing, borders, sizes, and layouts.

1. CSS Syntax

A CSS rule consists of a selector and one or more declarations:

selector {
    property: value;
}

For example:

p {
    color: navy;
    font-size: 1rem;
}
  • p -- The selector. It chooses which HTML elements will be styled.
  • color and font-size -- Properties that describe what will change.
  • navy and 1rem -- Values assigned to the properties.
  • ; -- Separates declarations. It should be added after every declaration.

CSS comments are written like this:

/* This is a CSS comment */

2. Three Ways to Add CSS

Inline CSS

<p style="color: red;">Red text</p>

Inline CSS affects one element. It is useful for quick experiments, but it becomes difficult to maintain when used throughout a page.

Internal CSS

<head>
    <style>
        p {
            color: red;
        }
    </style>
</head>

Internal CSS is placed inside a <style> element in the document's <head>. It is suitable for small pages and exercises.

External CSS

<link rel="stylesheet" href="style.css">

The link is placed inside <head>, while the rules are stored in a separate style.css file:

p {
    color: red;
}

An external stylesheet is usually the best option because it separates the HTML structure from its appearance and can be reused by multiple pages.

3. CSS Selectors

Selectors tell the browser which elements should receive a set of styles.

  • p { ... } -- Selects every <p> element.
  • .card { ... } -- Selects every element with class="card". Classes can be reused.
  • #contact { ... } -- Selects the element with id="contact". An ID must be unique on the page.
  • .card p { ... } -- Selects every paragraph located inside an element with the card class.
  • h1, h2, h3 { ... } -- Applies the same declarations to several selectors.
  • * { ... } -- The universal selector; it selects every element.

Use classes for reusable styles. IDs are mainly useful for unique page targets, labels, and JavaScript hooks.

<article class="card featured" id="first-card">
    Card content
</article>

An element may have more than one class, separated by spaces.

4. Pseudo-classes

A pseudo-class selects an element in a particular state:

a:hover {
    color: red;
}

input:focus {
    outline: 3px solid royalblue;
}

button:active {
    transform: scale(0.98);
}

li:first-child {
    font-weight: bold;
}
  • :hover -- The pointer is over the element.
  • :focus -- The element has keyboard or input focus.
  • :focus-visible -- Focus should be visibly indicated, usually during keyboard navigation.
  • :active -- The element is currently being activated, for example while a button is pressed.
  • :first-child and :last-child -- Select an element according to its position among siblings.

Never remove a focus outline without providing another clearly visible focus style. Keyboard users need it to know which control is active.

5. The Cascade, Specificity, and Inheritance

The word "cascading" describes how the browser chooses between competing rules. It considers importance, selector specificity, and source order.

  1. Inline styles are more specific than ordinary stylesheet rules.
  2. An ID selector such as #warning is more specific than a class.
  3. A class or pseudo-class such as .note or :hover is more specific than an element selector.
  4. An element selector such as p has the lowest specificity in this list.
  5. When specificity is equal, the rule written later wins.
p { color: blue; }
.note { color: green; }
#warning { color: red; }

A paragraph with both class="note" and id="warning" will be red. Avoid !important in normal code because it makes future overrides harder.

Some properties, especially color and font-family, are inherited by child elements. Layout properties such as margin, padding, and border are generally not inherited.

6. The Box Model

Every HTML element is treated as a rectangular box made of four layers:

  1. content -- The text, image, or other content.
  2. padding -- Space between the content and border.
  3. border -- The line surrounding the padding and content.
  4. margin -- Space outside the border, separating the element from its neighbors.
.card {
    width: 300px;
    padding: 20px;
    border: 2px solid black;
    margin: 30px;
}

With the default content-box sizing, the visible width is 300px + 40px padding + 4px border = 344px. Margin adds space around that box.

A common reset makes declared widths include the padding and border:

* {
    box-sizing: border-box;
}

With border-box, the same element has a total visible width of 300px.

Spacing shorthand

padding: 20px;                 /* all sides */
padding: 10px 20px;            /* top/bottom, left/right */
padding: 10px 20px 30px;       /* top, left/right, bottom */
padding: 10px 20px 30px 40px;  /* top, right, bottom, left */

The same shorthand rules apply to margin. Individual sides can be set with properties such as margin-top, padding-left, and border-bottom.

7. Width and Height

.container {
    width: 90%;
    max-width: 1000px;
    min-height: 300px;
    margin: 0 auto;
}
  • width and height -- Set preferred dimensions.
  • min-width and min-height -- Prevent an element from becoming smaller than a limit.
  • max-width and max-height -- Prevent an element from becoming larger than a limit.
  • margin: 0 auto -- Horizontally centers a block that has a limited width.

Avoid a fixed height for text containers unless it is truly required. Growing content can overflow a box with a fixed height.

8. CSS Units

  • px -- A fixed CSS pixel. It is useful for borders and small visual details.
  • % -- A percentage usually calculated from a related size of the parent element.
  • rem -- Relative to the root <html> font size. By default, 1rem is usually 16px.
  • em -- Relative to the current element's font size. It is useful when spacing should scale with a component's text.
h1 {
    font-size: 2rem;
}

button {
    font-size: 1rem;
    padding: 0.5em 1em;
}

img {
    width: 100%;
}

A practical starting point is to use rem for typography and most spacing, percentages for flexible widths, px for fine details, and em for dimensions tied to a component's font size.

9. Colors

color changes the foreground text color, while background-color changes the background.

.example {
    color: #222222;
    background-color: rgb(245, 245, 245);
    border-color: hsl(210, 50%, 40%);
}

Common color formats include named colors such as red, hexadecimal values such as #ff0000, rgb(), rgba() with transparency, and hsl().

Repeated colors can be stored in custom properties:

:root {
    --color-primary: #176b4d;
    --color-text: #202020;
    --color-background: #f4f1ea;
}

body {
    color: var(--color-text);
    background-color: var(--color-background);
}

Always maintain strong contrast between text and its background so that the content remains readable.

10. Fonts and Text

body {
    font-family: Georgia, "Times New Roman", serif;
    font-size: 1rem;
    line-height: 1.6;
}

h1 {
    font-size: 2.5rem;
    font-weight: 700;
    text-align: center;
}
  • font-family -- Sets the typeface. Provide fallback fonts and finish with a generic family such as serif or sans-serif.
  • font-size -- Sets the text size.
  • font-weight -- Sets thickness, commonly 400 for regular and 700 for bold.
  • line-height -- Controls vertical space between lines.
  • text-align -- Aligns inline content left, right, or center.
  • text-decoration -- Adds or removes decorations such as underlines.
  • text-transform -- Changes capitalization, for example with uppercase.

11. Block, Inline, and Display

Block elements such as <div>, <section>, and <p> normally begin on a new line and use the available width. Inline elements such as <span> and <a> flow within a line and use only the space their content needs.

a {
    display: inline-block;
}

.hidden {
    display: none;
}
  • display: block -- Creates a block-level box.
  • display: inline -- Creates an inline box; width and height do not behave like they do on a block.
  • display: inline-block -- Flows inline but accepts dimensions and padding like a block.
  • display: none -- Removes the element from both the page and its layout.
  • display: flex -- Turns an element into a Flexbox container.

12. Flexbox Basics

Flexbox arranges a group of items along one main direction. The parent is the flex container, and its direct children are flex items.

<div class="cards">
    <article class="card">First</article>
    <article class="card">Second</article>
    <article class="card">Third</article>
</div>
.cards {
    display: flex;
    flex-direction: row;
    gap: 1rem;
}

Direction and axes

  • row -- Items run horizontally. This is the default.
  • row-reverse -- Items run horizontally in reverse order.
  • column -- Items run vertically.
  • column-reverse -- Items run vertically in reverse order.

With flex-direction: row, the main axis is horizontal and the cross axis is vertical. With column, the axes switch.

Alignment

.cards {
    display: flex;
    justify-content: space-between;
    align-items: center;
}

justify-content aligns items on the main axis. Common values are flex-start, center, flex-end, space-between, space-around, and space-evenly.

align-items aligns items on the cross axis. Common values are stretch, flex-start, center, and flex-end.

Wrapping and gaps

.cards {
    display: flex;
    flex-wrap: wrap;
    gap: 1rem;
}

flex-wrap: wrap allows items to move onto a new line when there is not enough room. gap adds consistent spacing between items without requiring margins on every child.

Flexible item sizes

.card {
    flex: 1 1 250px;
}

This is shorthand for flex-grow: 1, flex-shrink: 1, and flex-basis: 250px. The card starts around 250px wide, may grow into free space, and may shrink when necessary.

16. CSS Nesting

CSS nesting lets you write rules for elements inside a parent selector without repeating the parent selector. For example, these nested rules:

article {
    ul,
    ol {
        display: grid;
        gap: 5px;
    }

    table {
        width: 100%;
        border-collapse: collapse;
    }

    th,
    tfoot td {
        text-align: left;
    }
}

are equivalent to selectors such as article ul, article ol, article table, article th, and article tfoot td. Use & when you want to attach a pseudo-class or another selector directly to the parent, as in &:hover, which selects the hovered article itself.

Nesting helps keep related styles together, but it is optional. Modern browsers support native CSS nesting; check browser requirements if your page needs to work in older browsers.

17. Browser Developer Tools

Press F12 or open the browser's developer tools and select the Elements or Inspector tab. Developer tools allow you to:

  • Inspect which CSS rules apply to an element.
  • See overridden declarations shown with a line through them.
  • Edit values temporarily and observe the result immediately.
  • Inspect an element's box model.
  • Visualize and debug Flexbox layouts.
  • Test the page at different viewport widths.

Changes made in developer tools disappear when the page is refreshed, so transfer successful experiments into the stylesheet.

Week 3 - CSS Layout and Responsiveness

Goal: arrange elements on a page and make the layout work on phones, tablets, and computers.

The main rule: build your main layout with normal flow, Flexbox, or Grid. Use position for specific tasks, such as a badge on a card or a sticky menu.

The examples are independent. Classes such as .container and .card are names chosen by the author, not special CSS commands. Give the HTML element the matching class to apply a rule.

1. Start Here: Normal Flow

The browser already knows how to arrange elements without extra positioning. This is called normal flow:

  • Block elements, such as <div> and <p>, start on a new line by default.
  • Inline elements, such as <span> and <a>, sit alongside text while there is enough space.
  • HTML order affects the order on the page. A longer paragraph normally pushes the following elements down.

Which tool should you choose?

  • Text, headings, and sections below each other: normal flow.
  • A row of buttons, a menu, or an icon next to text: Flexbox. You mainly control one direction: a row or a column.
  • A card grid or content with a sidebar: Grid. You control columns and rows together.
  • A badge in a card corner: position: absolute inside a parent with position: relative.
  • An element that stays in a screen corner: position: fixed.
  • A menu that sticks while scrolling: position: sticky.

You can combine these tools: Grid for the page, Flexbox for buttons inside a card, and absolute for its badge.

2. Spacing and Centering Without Guesswork

  • margin -- space outside an element.
  • padding -- space inside an element, between its content and border.
  • gap -- space between items in a Flexbox or Grid container. Set it on the parent.

A container centered on the page

.container {
    box-sizing: border-box;
    width: 100%;
    max-width: 70rem;
    margin-inline: auto;
    padding-inline: 1rem;
}

The container uses the available width but never becomes wider than 70rem. margin-inline: auto shares the free space between both sides, and padding-inline adds space at the edges. margin: auto alone does not mean vertical centering.

Centering horizontally and vertically

.center {
    display: flex;
    justify-content: center;
    align-items: center;
    min-height: 12rem;
    gap: 1rem;
}

With the default flex-direction: row, justify-content aligns horizontally and align-items aligns vertically. With column, the axes switch. The parent needs free space in a direction for centering to be visible.

Avoid this: do not set left: 300px just to make something look centered. It will no longer be centered when the screen width changes.

3. CSS Grid: Columns, Rows, and Grid-template

Imagine a sheet of graph paper. The parent defines the grid, and its direct children occupy the cells.

<div class="grid">
    <div>Card 1</div>
    <div>Card 2</div>
    <div>Card 3</div>
    <div>Card 4</div>
</div>
.grid {
    display: grid;
    grid-template-columns: 1fr 1fr;
    grid-template-rows: auto auto;
    gap: 1rem;
}
  • display: grid turns the parent into a grid container.
  • grid-template-columns: 1fr 1fr creates two columns that share the available space equally, as long as their content's minimum sizes allow it.
  • fr means a share of available space after accounting for gaps and other track sizes. 1fr 2fr shares that space in a 1-to-2 ratio.
  • grid-template-rows: auto auto defines two rows whose heights adapt to their content.
  • gap: 1rem adds space between columns and rows, but not around the outer edge of the grid.

Result: the first two cards are in the first row, and the next two are in the second row.

Useful patterns

  • repeat(3, 1fr) -- three columns; a shorter way to write 1fr 1fr 1fr.
  • 14rem 1fr -- a 14rem sidebar next to flexible content.
  • repeat(3, minmax(0, 1fr)) -- three equal, flexible columns that can shrink below their content's minimum width. Long content may still need wrapping or scrolling.

grid-template is a shorthand. This example defines two rows before the slash and two columns after it:

.grid {
    grid-template: auto auto / 1fr 1fr;
}

As a beginner, you can use grid-template-columns and grid-template-rows separately -- they are easier to read. If you do not define rows, or more cards need extra rows, Grid creates additional rows automatically by default.

4. Grid: Placing and Aligning Items

Set grid-column and grid-row on the child, not on the container.

.wide-card {
    grid-column: 1 / -1;
}

.featured-card {
    grid-column: 1 / 3;
    grid-row: 1 / 3;
}
  • grid-column: 1 / -1 -- from the first to the last line of the explicitly defined grid, spanning all its columns.
  • grid-column: 1 / 3 -- from line 1 to line 3, spanning two columns. Three columns have four boundary lines.
  • grid-row: 1 / 3 -- the same idea for rows: span two rows.

Add class="wide-card" to one of the cards in the previous example to see the change.

Alignment inside cells

.grid {
    justify-items: center;
    align-items: center;
}

.special-card {
    justify-self: end;
    align-self: start;
}

In a typical layout with horizontal text, justify-items aligns children horizontally and align-items aligns them vertically inside their cells. place-items: center is a shorthand for centering in both directions.

justify-self and align-self change the alignment of just one child. By default, items without fixed dimensions usually stretch to fill their cells (stretch).

Note: text-align: center aligns text and inline content inside an element, not the card itself within the grid. Keep the visual order consistent with the logical HTML order.

5. Responsiveness, Media Queries, and Mobile-first

A responsive page adapts its layout to the available space. Instead of shrinking a desktop page, you might change three columns into one.

Mobile-first means writing a simple layout for small screens first, then adding changes for wider screens with min-width.

.cards {
    display: grid;
    grid-template-columns: 1fr;
    gap: 1rem;
}

@media (min-width: 768px) {
    .cards {
        grid-template-columns: repeat(2, minmax(0, 1fr));
    }
}

@media (min-width: 1024px) {
    .cards {
        grid-template-columns: repeat(3, minmax(0, 1fr));
    }
}
  • Below 768px: one column from the base rule.
  • From 768px to below 1024px: two columns.
  • From 1024px: three columns. Both conditions match, but the later rule with the same specificity overrides the earlier one.

@media is a condition: the rules inside apply only when it matches. min-width means "at this width or wider," and max-width means "at this width or narrower." The browser checks the viewport width in CSS pixels, not the phone model.

A breakpoint is a threshold where the layout changes. The values 768px and 1024px are examples, not mandatory standards. Choose breakpoints where your content becomes too cramped or too spread out.

What else should you remember?

  • Add the viewport tag below inside <head>. This guide already includes it.
  • You do not need to repeat every style inside @media -- write only the changes.
  • Avoid a fixed width such as width: 1200px for the whole page. Use flexible widths and max-width.
  • For images, max-width: 100%; height: auto; is useful. Avoid a fixed height on sections with long text.

6. CSS Variables: Named Values

A CSS variable, also called a custom property, lets you name a value and reuse it in many places. Its name starts with --, and you read its value with var().

:root {
    --color-primary: #145db1;
    --space: 1rem;
    --radius: 0.5rem;
}

.button {
    background-color: var(--color-primary);
    color: white;
    padding: var(--space);
    border-radius: var(--radius);
}

.button--danger {
    --color-primary: #b42318;
}
  • :root selects the document's root element, which is <html> in HTML. It is a useful place for shared colors, spacing, and sizes.
  • Changing --color-primary in :root updates every use of that variable unless it has a local override.
  • Variables are inherited by default. An override on an element affects it and its descendants, not the whole page.
<button class="button">Save</button>
<button class="button button--danger">Delete</button>

The first button will be blue and the second red. Both use the same .button rule.

You can provide a fallback value, used, for example, when the variable has not been defined:

.panel {
    background-color: var(--color-surface, white);
}

This project already uses --gray-test-color in the same way. A CSS variable stores a style value; it is not a JavaScript condition or function.

7. Position: Static, Relative, Absolute, Fixed, and Sticky

position controls how an element is positioned. Depending on the mode, top, right, bottom, and left set offsets from reference edges or from the original position. They have no effect with static.

Value Keeps its space in the layout? Reference point
static Yes Normal flow; top/left do not move it.
relative Yes Its own original position.
absolute No The nearest ancestor that creates a containing block, usually with a position other than static.
fixed No Usually the browser viewport.
sticky Yes The nearest ancestor with a scrolling mechanism; its containing block limits movement.

Static: the default

position: static means normal positioning. You usually do not need to write it.

Relative: move visually, but keep the space

.box {
    position: relative;
    top: 8px;
    left: 12px;
}

The element moves 8px down and 12px right from its original position. Other elements behave as if it were still in its old place, so it may overlap them.

A common use of relative is not moving an element, but creating a reference point for a child with absolute. In that case, you do not need top or left.

Absolute: a badge in a card corner

<div class="card">
    <span class="card__badge">New</span>
    <h4>Product card</h4>
    <p>Product description.</p>
</div>
.card {
    position: relative;
    padding: 3rem 1rem 1rem;
    border: 1px solid #65686d;
}

.card__badge {
    position: absolute;
    top: 0.75rem;
    right: 0.75rem;
}

The parent has relative; the child has absolute. The badge sits in the card's top-right corner. Extra top padding reserves space for it because the badge itself takes no space in normal flow.

New

Product card

The badge is attached to this card, not to the whole screen.

If the parent does not create a reference point, the browser searches further up the ancestor chain. If none is found, the initial containing block becomes the reference, not this card. This is why a badge can appear somewhere else on the page.

Fixed: a constant position in the viewport

.help-button {
    position: fixed;
    right: 1rem;
    bottom: 1rem;
    z-index: 20;
}

The help button stays in the bottom-right corner while you scroll. It does not reserve space in the layout, so make sure it does not cover text or other buttons, including when the page is zoomed in.

An exception to remember: an ancestor with, for example, transform can become the reference for fixed. If an element does not stay attached to the viewport, check its ancestors' styles.

Sticky: stick when scrolling reaches a threshold

.sticky-menu {
    position: sticky;
    top: 1rem;
    align-self: start;
}

The menu starts in its normal position. When scrolling brings it to the top: 1rem threshold, it stays near that edge as long as its container's boundaries allow it. This is not the same as fixed.

  • Set a threshold, such as top: 0 or top: 1rem. Without one, the element will not stick along that axis.
  • The container must be tall enough to allow movement. Adding sticky to an element as tall as its parent is not enough.
  • Check ancestors' overflow. Values such as auto, scroll, or hidden can change which ancestor controls the sticking behavior.
  • In Grid or Flexbox, stretching an item can leave no room for movement. In a suitable layout, align-self: start helps, as in the example below.

Also, inset is a shorthand for top, right, bottom, and left. For example, inset: 0 sets all four offsets to zero.

8. Z-index: Which Element Is on Top?

z-index controls the order of overlapping layers. A larger number means a higher layer within the same stacking context. The number has no px unit.

.lower-layer {
    position: relative;
    z-index: 1;
}

.upper-layer {
    position: relative;
    z-index: 2;
}
  • You usually apply z-index to an element with a position other than static.
  • Exception: Flexbox or Grid items can use z-index without changing position.
  • z-index does not move elements or create spacing. It controls what appears in front when elements overlap.

Why does z-index: 9999 sometimes not help?

A stacking context is a separate group of layers. It can be created by, for example, position: relative together with z-index: 1, a transform, or opacity below 1.

Imagine two boxes: box A is below box B. Even a very large z-index on a child inside box A cannot lift it above the whole of box B. Check the parents' layers first instead of increasing the number blindly.

If an element is clipped by a parent's overflow: hidden, increasing z-index will not remove that clipping either.

9. Recipe: A Responsive Layout with Named Areas

grid-template-areas lets you draw a layout using names. grid-area assigns a child to an area. Place this HTML inside <body> on a separate practice page:

<div class="site">
    <header class="site__header">Header</header>
    <aside class="site__menu">Sidebar menu</aside>
    <main class="site__content">
        <h1>Page content</h1>
        <p>Add cards and longer text here.</p>
    </main>
    <footer class="site__footer">Footer</footer>
</div>
.site {
    display: grid;
    grid-template-columns: 1fr;
    grid-template-areas:
        "header"
        "menu"
        "content"
        "footer";
    gap: 1rem;
    max-width: 70rem;
    margin-inline: auto;
    padding: 1rem;
}

.site__header {
    grid-area: header;
}

.site__menu {
    grid-area: menu;
}

.site__content {
    grid-area: content;
    min-width: 0;
}

.site__footer {
    grid-area: footer;
}

@media (min-width: 768px) {
    .site {
        grid-template-columns: 14rem minmax(0, 1fr);
        grid-template-areas:
            "header header"
            "menu content"
            "footer footer";
    }

    .site__menu {
        position: sticky;
        top: 1rem;
        align-self: start;
    }
}
  • Small screen: everything is in one column: header, menu, content, then footer.
  • From 768px: the menu is 14rem wide, and the content takes the remaining space. The header and footer span both columns.
  • A repeated name, such as "header header", means one area spanning two cells. Each named area must form a rectangle.
  • min-width: 0 lets the content item shrink. Long code should still have its own scrolling with overflow-x: auto.
  • Add plenty of content to .site__content to see the menu's sticky behavior. The menu should not be taller than the available viewport height.

Remember: Flexbox = one main direction; Grid = columns and rows; media query = a condition for applying styles; CSS variable = a named value; relative = a reference point with its space preserved; absolute = positioning within a containing block without reserving space; fixed = usually relative to the viewport; sticky = sticking within container boundaries; z-index = layer order.

Week 4 - Colors, Fonts, and Units

Goal: create a consistent visual style with readable text, accessible colors, and flexible measurements.

Week 2 introduced the basic CSS properties. This week focuses on choosing values that work together and remain readable on different screens.

1. Build a Consistent Color Palette

CSS supports named colors, hexadecimal values, and functional formats such as rgb() and hsl(). Use a small palette with clear roles rather than choosing a new color for every element.

:root {
    --color-text: #20242a;
    --color-background: #f7f8fa;
    --color-primary: hsl(220, 70%, 40%);
    --color-accent: #e6a23c;
}

body {
    color: var(--color-text);
    background-color: var(--color-background);
}

a {
    color: var(--color-primary);
}
  • #rrggbb -- Hexadecimal red, green, and blue channels; shorthand such as #369 is also supported.
  • rgb(20 80 160) -- Sets red, green, and blue channel values.
  • hsl(220 70% 40%) -- Sets hue, saturation, and lightness, which can make related shades easier to create.
  • rgb(20 80 160 / 50%) -- Adds transparency. Transparent text can become difficult to read over changing backgrounds.

Check text and background contrast, including link, hover, and focus states. Do not use color alone to communicate meaning; pair it with text, an icon, or another visual cue.

2. Make Typography Readable

Choose a font stack with fallbacks so text remains available if the preferred font is not installed. Use a comfortable line height and a limited set of sizes to create a clear heading hierarchy.

body {
    font-family: Arial, Helvetica, sans-serif;
    font-size: 1rem;
    line-height: 1.6;
}

h1,
h2,
h3 {
    line-height: 1.2;
}

h1 {
    font-size: 2.25rem;
}

.muted {
    color: #555b64;
}

.label {
    font-weight: 700;
    letter-spacing: 0.04em;
    text-transform: uppercase;
}
  • font-family -- Lists preferred fonts followed by fallbacks and a generic family.
  • font-size -- Sets the size of text; relative sizes respect user preferences better than fixed pixel sizes.
  • font-weight -- Sets emphasis, commonly from 400 (regular) to 700 (bold).
  • line-height -- Controls space between lines. A unitless value such as 1.6 scales with the font size.
  • letter-spacing -- Adjusts space between characters; use it sparingly, especially for body text.

Keep paragraphs to a comfortable line length and make sure small or muted text still has enough contrast. Avoid using font size or color as the only way to identify an important action.

3. Choose the Right CSS Unit

Different units respond to different things. Pick one based on what should control the size:

  • px -- A CSS pixel, useful for small details such as a thin border or focus outline.
  • rem -- Relative to the root font size; useful for consistent text sizes and spacing across the page.
  • em -- Relative to the element's font size; useful when a component's padding should scale with its text.
  • % -- Relative to a related value, often the parent's size; useful for flexible widths.
  • vw and vh -- Relative to the viewport width and height; useful for some screen-based sizing, but avoid making text depend only on them.
  • ch -- Based on the width of the “0” character; useful for limiting text line length.
  • Unitless numbers -- Used by properties such as line-height and opacity; do not add px to them.
.article {
    width: min(100% - 2rem, 65ch);
    margin-inline: auto;
    padding: 1.5rem;
}

.button {
    padding: 0.6em 1em;
    border: 2px solid currentColor;
}

.title {
    font-size: clamp(2rem, 5vw, 3.5rem);
}

min() keeps the article within the available width while limiting long lines. em makes button padding follow its text size. clamp() lets the title grow with the viewport while enforcing a minimum and maximum size.

Do not set a fixed height on text containers just to fit one screen size. Content can wrap differently when the viewport changes or the user zooms in.

Summary

Use a small, reusable color palette and check contrast. Choose font fallbacks, establish a text hierarchy, and give body text comfortable line spacing. Use relative units for most typography and spacing, reserving pixels for fine details. Test the result at different viewport sizes and zoom levels.

Week 5 - Flexbox and CSS Grid

Goal: confidently build flexible rows, columns, card galleries, and complete page layouts. Learn which properties belong on the parent, which belong on its children, and how to debug layouts that do not behave as expected.

Weeks 2 and 3 introduced these layout tools. This week explains them in detail. The official name of the two-dimensional layout system is CSS Grid, not Gridbox.

How to use the examples: code snippets are independent examples. Use the matching HTML and CSS together in a separate page with its own stylesheet. Classes such as .cards are ordinary names, not built-in CSS commands. The visible demos below use separate classes so they do not change the rest of this guide.

1. Flexbox or Grid: Which One Should You Use?

Flexbox is one-dimensional: it lays items out along one main axis, either a row or a column. It can wrap, but each line distributes its space independently. Grid is two-dimensional: it defines rows and columns together, so items on different rows can share the same column boundaries.

Question Flexbox CSS Grid
What do you control? One main direction; each wrapped line behaves independently. Rows and columns, including items spanning multiple tracks.
Typical uses Menus, toolbars, button groups, an icon beside text, or a vertical card. Galleries, dashboards, a sidebar with content, or a whole page layout.
What drives the layout? Often the items' content and how they share available space. Often the tracks you define and where items sit within them.
Can you combine them? Yes. Use Grid for a card gallery and Flexbox inside each card.

These are guidelines, not restrictions. Both tools can build many of the same layouts. Choose the one that expresses your intention most clearly, rather than using absolute positioning or lots of manual offsets.

2. Containers and Items: The Parent-child Rule

<div class="layout">
    <div class="item">First</div>
    <div class="item">
        <span>Inside the second item</span>
    </div>
    <div class="item">Third</div>
</div>
.layout {
    display: flex; /* or display: grid */
    gap: 1rem;
}
  • The element with display: flex or display: grid is the container.
  • Its direct children become flex items or grid items. The nested <span> is not an item of .layout.
  • Container properties control the group: direction, tracks, gaps, and shared alignment.
  • Item properties control one child: flexible sizing, placement, or individual alignment.
  • An item can also be a container for its own children. This is how nested layouts work.

display: inline-flex and display: inline-grid use the same internal layout systems, but the container itself participates in surrounding inline flow instead of behaving as a block-level box.

3. Flexbox: Direction and Axes

.layout {
    display: flex;
    flex-direction: row;
    gap: 1rem;
}
  • row -- Along the inline direction; usually left to right in an English page. This is the default.
  • row-reverse -- The same axis, with the start and end reversed.
  • column -- Along the block direction; usually top to bottom.
  • column-reverse -- The column direction reversed.

The main axis follows flex-direction. The cross axis runs perpendicular to it. In normal horizontal writing, row has a horizontal main axis and column has a vertical main axis.

Remember axes, not just horizontal and vertical: justify-content works along the main axis; align-items works along the cross axis. Text direction and writing mode can also affect the actual directions.

4. Flexbox: Aligning Items and Distributing Space

.toolbar {
    display: flex;
    justify-content: space-between;
    align-items: center;
    gap: 1rem;
    min-height: 6rem;
}

.toolbar__special {
    align-self: flex-end;
}

justify-content: the main axis

  • flex-start -- Pack items at the main start.
  • flex-end -- Pack items at the main end.
  • center -- Pack items in the center.
  • space-between -- Equal free space between items, with no added space at the outer ends.
  • space-around -- Equal space around each item; outer spaces are half the spaces between items.
  • space-evenly -- Equal free space between items and at both outer ends.

Space distribution needs leftover space. If growing items already fill the main axis, justify-content has no extra space to distribute. gap still provides spacing between items.

align-items: the cross axis

  • stretch -- Items with an automatic cross size stretch across their line. This is the usual default behavior.
  • flex-start, center, and flex-end -- Align at the start, center, or end of the cross axis.
  • baseline -- Align text baselines; useful for labels or controls with different font sizes.
  • align-self -- Set on a child to override the container's align-items for that one item.
.centered {
    display: flex;
    justify-content: center;
    align-items: center;
    min-height: 12rem;
}

This centers children on both axes. The min-height creates vertical room without forcing a fixed height that could clip longer content.

Common trap: justify-items and justify-self do not align flex items. Use justify-content, flexible sizing, or auto margins instead. In Flexbox, place-items: center does not replace both centering declarations above.

5. Flexbox: Wrapping, Gaps, and Multiple Lines

.cards {
    display: flex;
    flex-wrap: wrap;
    gap: 1rem;
}

.card {
    flex: 1 1 14rem;
    min-width: 0;
}
  • flex-wrap: nowrap -- Keep a single line. This is the default; items may shrink or overflow.
  • flex-wrap: wrap -- Allow additional lines when items do not fit.
  • flex-wrap: wrap-reverse -- Allow wrapping with the cross-axis stacking direction reversed.
  • flex-flow: row wrap -- Shorthand for flex-direction and flex-wrap.
  • gap: 1rem -- Set both row and column gaps. gap: 1rem 2rem sets row gap first, column gap second.

row-gap and column-gap can be written separately. Gaps separate items or lines; they do not add padding around the container's edges. With column, row gaps separate items down a column and column gaps separate wrapped columns.

align-content is not align-items

align-items aligns items inside each line. align-content arranges the lines themselves along the cross axis when a wrapping flex container has extra cross-axis space.

.multi-line {
    display: flex;
    flex-wrap: wrap;
    min-height: 20rem;
    align-items: center;
    align-content: space-between;
    gap: 1rem;
}

Useful align-content values include flex-start, flex-end, center, stretch, space-between, space-around, and space-evenly. It does not arrange lines in a nowrap container. Wrapping a column also requires a constrained available height; otherwise the column can simply keep growing.

6. Flexbox Items: Grow, Shrink, and Basis

Set these properties on the children, not the container:

.card {
    flex-grow: 1;
    flex-shrink: 1;
    flex-basis: 14rem;
}

/* The same settings as a shorthand */
.card {
    flex: 1 1 14rem;
}
  • flex-basis -- The starting main-axis size before free space is distributed. For a row this is usually width; for a column, height.
  • flex-grow -- A unitless share of positive free space. 0 means do not grow; items with 1 and 2 receive free space in a 1-to-2 ratio.
  • flex-shrink -- A unitless factor for giving up space when items are too large. Shrinking is weighted by the basis, so equal factors do not necessarily remove equal numbers of pixels.

For example, in a 600px row without gaps, two items with a 100px basis leave 400px free. With grow factors 1 and 3, they receive 100px and 300px extra, ending at 200px and 400px, assuming no min/max constraints. Grow factors divide extra space, not necessarily final widths.

Common flex shorthand values

  • flex: 0 1 auto -- The initial behavior: start from the automatic basis, do not grow, but allow shrinking.
  • flex: auto -- Equivalent to 1 1 auto; grow and shrink from an automatic basis.
  • flex: none -- Equivalent to 0 0 auto; do not grow or shrink.
  • flex: 1 -- Browsers expand it to 1 1 0%; a common equal-space pattern. Content minimums can still prevent equal sizes, and a percentage basis can behave differently in an indefinite-height column.
  • flex: 1 1 0 -- An explicit zero-length basis; useful when you want to share space without using content as the starting size.
  • flex: 0 0 12rem -- A 12rem basis with no growth or shrinking. This can overflow a smaller container.

flex-basis: auto uses the main-size property, such as width in a row, when that property provides a definite size; otherwise it is content-based. A non-auto basis is used instead of that width or height as the starting flex size. Minimum and maximum sizes still constrain the final result.

Why will an item not shrink?

.card {
    flex: 1 1 14rem;
    min-width: 0;
    overflow-wrap: anywhere;
}

.card pre {
    overflow-x: auto;
}

Flex items often have an automatic minimum size based on their content. min-width: 0 lets an item in a row shrink below that minimum, while wrapping text or scrolling code handles the content itself. In a height-constrained column layout, min-height: 0 can solve the equivalent vertical problem.

7. Flexbox Recipes: Auto Margins and Vertical Cards

Push one item to the end of a toolbar

<div class="toolbar">
    <span>Project name</span>
    <button class="toolbar__action" type="button">Save</button>
</div>
.toolbar {
    display: flex;
    align-items: center;
    gap: 1rem;
}

.toolbar__action {
    margin-inline-start: auto;
}

In a normal row, the auto margin absorbs available space before the action, pushing it toward the end. Unlike space-between, it can separate a specific item from a group. Auto margins take available space before alignment distributes what is left.

Keep actions at the bottom of a card

.card {
    display: flex;
    flex-direction: column;
    gap: 1rem;
    padding: 1rem;
}

.card__actions {
    margin-block-start: auto;
    display: flex;
    flex-wrap: wrap;
    gap: 0.5rem;
}

The card needs extra height for the auto margin to absorb. A Grid gallery that stretches cards to the same row height provides that space naturally. Avoid hard-coded card heights just to line up buttons.

Visual order is not reading order

order works on flex and grid items. Its default is 0; lower values appear first, with equal values following source order. Reverse directions and order change visual placement, not the logical HTML order or normal keyboard focus order. Write a sensible source order first; do not use CSS reordering to repair confusing markup.

8. Grid: Tracks, Lines, Cells, and Areas

<div class="grid">
    <div>Card 1</div>
    <div>Card 2</div>
    <div>Card 3</div>
    <div>Card 4</div>
    <div>Card 5</div>
    <div>Card 6</div>
</div>
.grid {
    display: grid;
    grid-template-columns: repeat(3, minmax(0, 1fr));
    gap: 1rem;
}
  • Track: the space between two adjacent grid lines; a column or a row.
  • Line: a boundary between tracks. Three columns have four column lines.
  • Cell: the intersection of one row and one column.
  • Area: a rectangle made from one or more cells.
  • Explicit grid: tracks defined by properties such as grid-template-columns and grid-template-rows.
  • Implicit grid: extra tracks created when placement needs more space than the explicit grid provides.

By default, Grid places these children across a row, then creates additional rows as needed. Columns remain aligned across those rows, unlike independently wrapping flex lines.

9. Grid: Defining Column and Row Sizes

.dashboard {
    display: grid;
    grid-template-columns: 14rem minmax(0, 1fr);
    grid-template-rows: auto 1fr auto;
    min-height: 30rem;
    gap: 1rem;
}

Track sizing values

  • 14rem or 200px -- A fixed track size; useful for a sidebar, but it must still fit the available space.
  • 1fr -- One share of leftover space after gaps and other track sizes are accounted for. 1fr 2fr shares that space in a 1-to-2 ratio, subject to content minimums.
  • auto -- Content-aware sizing; auto tracks can also stretch when space is available.
  • min-content -- The smallest intrinsic size, often constrained by the longest unbreakable part of the content.
  • max-content -- The intrinsic size without taking optional line breaks; long text can make this very wide.
  • minmax(12rem, 1fr) -- A track with a minimum of 12rem and a flexible maximum.
  • minmax(0, 1fr) -- A flexible track that can shrink below its content's automatic minimum. Content still needs wrapping or scrolling.
  • fit-content(20rem) -- A content-sized track with a preferred cap of 20rem; its intrinsic minimum can still exceed that cap.
/* Three equal flexible columns */
grid-template-columns: repeat(3, minmax(0, 1fr));

/* One narrow column and one wider column */
grid-template-columns: minmax(0, 1fr) minmax(0, 2fr);

/* Two explicit content-sized rows */
grid-template-rows: auto auto;

/* Shorthand: rows before the slash, columns after it */
grid-template: auto auto / repeat(3, minmax(0, 1fr));

repeat() avoids repeating track definitions manually. grid-template can also include named areas; separate properties are often easier to understand while learning.

Common trap: 50% 50% already consumes the container's width, so an added column gap can cause overflow. Two fr tracks share the space after the gap is accounted for.

10. Grid Items: Placement, Spans, and Named Lines

Placement belongs on a grid item. Start and end values identify boundary lines, not column counts.

.featured {
    grid-column: 1 / 3;
    grid-row: 1 / 3;
}

.full-width {
    grid-column: 1 / -1;
}

.two-columns {
    grid-column: span 2;
}
  • grid-column: 1 / 3 -- Start at line 1 and end at line 3, spanning two columns.
  • grid-row: 1 / 3 -- Span two rows in the same way.
  • grid-column: 1 / -1 -- Span from the first to the last line of the explicit grid. Negative numbers count back from its end, not from the end of extra implicit tracks.
  • span 2 -- Occupy two tracks while letting auto-placement choose the starting position.
  • grid-column-start, grid-column-end, grid-row-start, and grid-row-end -- Longhand versions of these settings.

Named lines and grid-area shorthand

.layout {
    display: grid;
    grid-template-columns:
        [sidebar-start] 14rem
        [content-start] minmax(0, 1fr) [content-end];
}

.content {
    grid-column: content-start / content-end;
}

.featured {
    /* row-start / column-start / row-end / column-end */
    grid-area: 1 / 1 / 3 / 3;
}

Named lines make placement easier to read. grid-area can use four line values as above, or a single named area as in the next example.

Explicitly placing two items in the same area can make them overlap. That is useful for a deliberate image-and-caption layer, but it is not automatic collision avoidance. Check placement and use z-index only when layering is intentional.

11. Grid: Page Layouts with Named Areas

<div class="page-grid">
    <div class="page-grid__top">Top bar</div>
    <aside class="page-grid__sidebar">Sidebar</aside>
    <div class="page-grid__content">Main content</div>
    <div class="page-grid__bottom">Bottom bar</div>
</div>
.page-grid {
    display: grid;
    grid-template-columns: minmax(0, 1fr);
    grid-template-areas:
        "top"
        "sidebar"
        "content"

.page-grid__top { grid-area: top; }

.page-grid__content { grid-area: content; min-width: 0; }

    }

  • Each quoted string describes a row. Every row must have the same number of cells.
  • Repeating a name makes that area span cells. Every named area must form a rectangle; L-shaped areas are invalid.
  • A dot, such as "sidebar .", represents an unnamed cell.
  • Names are chosen by you, and the item's grid-area must match.
  • Change the area map in a media query without changing the HTML. Keep the visual sequence consistent with the reading order.

12. Grid: Automatic Placement and Implicit Tracks

.gallery {
    display: grid;
    grid-template-columns: repeat(3, minmax(0, 1fr));
    grid-auto-rows: minmax(8rem, auto);
    grid-auto-flow: row;
    gap: 1rem;
}
  • grid-auto-flow: row -- The default: auto-place across rows, adding rows as needed.
  • grid-auto-flow: column -- Auto-place down columns, adding columns as needed. Usually define rows first for this pattern.
  • grid-auto-rows -- Size automatically created rows. minmax(8rem, auto) gives them a minimum while allowing content to increase their height.
  • grid-auto-columns -- Size automatically created columns.
  • grid-auto-flow: row dense -- Look back for gaps that later items can fill.

Without dense, auto-placement generally advances instead of going back to fill earlier holes. With dense, the visual order can differ from the source order. Avoid it for content whose sequence matters or where keyboard navigation would become confusing.

If you accidentally place an item at grid-column: 5 in a three-column layout, Grid can create additional implicit columns. Unexpected extra tracks are often a placement mistake, not a reason to give the container a bigger width.

grid is a broader shorthand than grid-template: it can also configure or reset implicit-grid settings. Prefer explicit longhand properties until you understand which settings a shorthand resets.

13. Grid: Align Items or Align the Whole Grid?

In normal horizontal writing, justify works along the inline axis (usually horizontal), and align works along the block axis (usually vertical). Unlike Flexbox, these Grid axes do not switch based on a flex-direction.

Property Where? What does it move?
justify-items / align-itemsContainerAll items inside their own grid areas.
justify-self / align-selfOne itemThat item inside its grid area.
justify-content / align-contentContainerThe collection of tracks inside the container when there is free space.
 
.grid {
    display: grid;
    grid-template-columns: repeat(2, 6rem);
    grid-auto-rows: 5rem;
    min-height: 18rem;
    gap: 1rem;
    place-items: center;
    place-content: center;
}

.special {
    place-self: end start;
}
  • place-items -- Shorthand for align-items, then justify-items.
  • place-content -- Shorthand for align-content, then justify-content.
  • place-self -- Shorthand for align-self, then justify-self.
  • A single value applies to both parts. place-self: end start aligns at the block end and inline start.

Item alignment commonly uses start, end, center, stretch, or baseline. Content alignment also supports space distribution such as space-between and space-evenly.

Tracks sized with fr often already use all the available space, so centering the whole grid may have no visible effect. Grid items normally stretch when their dimensions allow it; items with an intrinsic aspect ratio, such as images, can behave differently. text-align: center only centers inline content inside a box, not the box in its grid area.

14. Responsive Grid: repeat(), auto-fit, and auto-fill

Adapt to available width without fixed breakpoints

.gallery {
    display: grid;
    grid-template-columns:
        repeat(auto-fit, minmax(min(100%, 14rem), 1fr));
    gap: 1rem;
}
  • repeat(auto-fit, ...) -- Create as many columns as fit, then collapse empty repeated tracks so occupied columns can expand.
  • minmax(..., 1fr) -- Give each column a minimum and allow it to share leftover space.
  • min(100%, 14rem) -- Use 14rem as the minimum when possible, but let it drop to the container width on a very narrow screen.

auto-fit versus auto-fill

auto-fill keeps the repeated tracks even when some are empty. auto-fit collapses empty ones. The difference is most visible when the container can fit more columns than there are items; with enough items to occupy every track, the results often look identical.

Neither value automatically makes a short last row fill the whole width if its columns are occupied elsewhere in the grid. That is different from a wrapping flex row.

Choose the automatic pattern when column count should follow available room. Choose media queries when the design needs a specific arrangement. Container queries are another option when a reusable component should respond to its container's width rather than the whole viewport.

16. Advanced Grid: Nested Grids and subgrid

An ordinary nested grid defines its own tracks independently. subgrid lets a nested grid reuse the parent tracks that it spans, so content inside different cards can line up with the same outer boundaries.

.comparison {
    display: grid;
    grid-template-columns:
        repeat(auto-fit, minmax(min(100%, 14rem), 1fr));
    gap: 1rem;
}

.comparison__card {
    display: grid;
    gap: 1rem;
}

@supports (grid-template-rows: subgrid) {
    .comparison__card {
        grid-row: span 3;
        grid-template-rows: subgrid;
    }
}

Use a card with three direct children: a heading, a description, and an action group. Each card spans three parent rows and shares those row tracks. The headings, descriptions, and actions can then align across neighboring cards, even when the text lengths differ.

grid-template-columns: subgrid shares column tracks instead. Subgrid is supported in modern browsers; check the project's supported versions. The @supports condition above keeps a simple independent grid as a fallback.

17. Common Mistakes and How to Debug Them

Problem What to check
The layout property does nothing.Is display: flex or grid on the correct parent? Is the target a direct child? Is another rule overriding yours?
Centering does not appear to work.Check the axes and whether there is free space. For Grid, distinguish item alignment from track alignment.
Flex items stay on one line.Add flex-wrap: wrap. Check the basis and available width; wrapping is not the default.
align-content has no effect in Flexbox.Use a wrapping container and leave extra cross-axis space. It is not a substitute for align-items.
A long word makes the page too wide.Check automatic minimum sizes: use min-width: 0 on the item, minmax(0, 1fr) for flexible grid tracks, and wrapping or scrolling for the content.
Two 50% columns overflow.The gap adds width on top of those percentages. Use flexible tracks such as repeat(2, minmax(0, 1fr)).
A span creates extra columns on mobile.A two-column span cannot fit a one-column explicit grid. Apply the span only at a suitable breakpoint.
Grid items overlap.Check explicit line placement or named areas. Two items can be assigned to the same cells.
Keyboard focus seems to jump around.Remove unnecessary order, reverse directions, or dense placement. Keep source and visual order consistent.
Text is clipped inside a card.Remove unnecessary fixed heights. Prefer content-sized rows or minmax(..., auto), and test longer text and zoom.

A practical DevTools checklist

  1. Inspect the container in the Elements or Inspector panel and confirm its computed display.
  2. Enable the Flexbox or Grid overlay to see axes, track boundaries, gaps, and line numbers.
  3. Inspect the child and check its basis, min/max sizes, placement, and inherited or overridden rules.
  4. Temporarily toggle one declaration at a time rather than adding random offsets.
  5. Test narrow and wide viewports, longer content, keyboard navigation, and at least 200% zoom.
  6. Copy successful changes back into the stylesheet; DevTools edits disappear on refresh.
